## Аннотация (Abstract)

Авторегрессионный инференс современных трансформаторных моделей опирается на конкатенацию контекста сессии в кэше ключей и значений (KV-кэш). Это влечет квадратичную вычислительную сложность $O(N^{2})$, деградацию внимания при сверхдлинных контекстах (Context Drift) и линейный рост расхода памяти пропорционально числу сессий. ZamiCore v2.3 формулирует архитектурную модель полного физического и математического разделения статического пространства параметров вычислителя ($P_S$) и динамической топологии сессионной задачи ($P_U$).

**ZamiCore v2.3** устраняет эту проблему за счет полного физического и математического разделения статического пространства весов ($P_S$) и динамического топологического ландшафта задачи ($P_U$).

### Ключевые инновации стандарта:
1. **Конический волновод с плоским дном (Flat-Bottom Waveguide / Semantic Funnel):** стратифицированное воздействие на промежуточных слоях трансформера ($l_{\mathrm{eq}} \dots l^{\ast}$), формирующее упругий коридор с нулевым потенциалом на дне. Это гарантирует сохранение 100% стохастической автономии модели на терминальных слоях рассуждения ($l > l^{\ast}$).
2. **Константный кадровый буфер (V-Buffer):** бессистемный (`lockless`) интерфейс размером 23 488 байт, функционирующий по принципу Uniform-буферов графических конвейеров (Vulkan SwapChain). Позволяет удерживать контекст как независимый «игровой уровень» и переключать сессии за $O(1)$ по времени (256 наносекунд).
3. **Топологический контур внешней памяти ($P_U$):** иерархия «Стволы — Рукава — Бассейны» на постоянных блочных накопителях (NVMe/ZFS), защищенная доменным шлюзом ингресса и стабилизированная алгоритмом гравитационной аккреции.
4. **Аппаратный Zero-Copy I/O-стек под FreeBSD:** прямое проецирование дисковых страниц по 4096 байт через `mmap(2)` и `madvise(2)`, анабиоз спящих веток через системный вызов `fspacectl(2)` (`SPACECTL_DEALLOC`) и асинхронное обслуживание прерываний Cold-Fault через кольцевые очереди ядра `kqueue(2)`.
5. **Трехзвенная подсистема артефактов кода (CAS):** изоляция черновых генераций в оперативной памяти (tmpfs), детерминированный шлюз верификации компилятором Clang и неизменяемое хранилище канонов на базе BLAKE3-хэшей с графом версий (DAG).

## 1. Архитектурная парадигма: V-Буфер как SwapChain, Контекст как игровой уровень

В классических решениях переключение контекста влечет полную инвалидацию или пересчет KV-кэша. ZamiCore разделяет память вычислителя по аналогии с низкоуровневыми графическими API (Vulkan / Direct3D 12):

* **Статические веса модели ($P_S$):** неизменяемые геометрические ассеты (Assets / Meshes), загруженные в оперативную память в режиме `PROT_READ` через `mmap(2)`. Веса остаются холодными и никогда не модифицируются ($\nabla W = 0$).
* **Константный буфер кадра (Uniform Buffer):** блок памяти строго фиксированного объема (23 488 байт), непрерывно разделяемый между потоком хоста и вычислительным циклом ядра.
* **Контекст задачи как независимый уровень (Mission / Level):** каждый диалог, анализируемый репозиторий или диагностическая сессия представляет собой независимый граф каньонов и бассейнов на диске. Переключение контекста не требует сброса состояния нейросети — управляющий поток атомарно перезаписывает дескриптор каньона в буфере кадра, мгновенно направляя внимание модели в русло нового уровня.

## 2. Контур 1: Семантический кремний и трехзонный волновод (Flat-Bottom Waveguide)

Для предотвращения энтропийного разброса без деградации рассудочной способности модели (устранение эффекта нейросетевой лоботомии) вычислительные слои разделяются на три функциональные зоны:

$$\mathcal{L}_1 = [0, \; l_{\mathrm{eq}} - 1], \quad \mathcal{L}_2 = [l_{\mathrm{eq}}, \; l^{\ast}], \quad \mathcal{L}_3 = [l^{\ast} + 1, \; L - 1]$$

```text
 ВХОД                                                                             ВЫХОД
 Слой 0                  Слой l_eq                  Слой l*                 Слой L_total
 ┌───────────────────────┬──────────────────────────┬───────────────────────┐
 │ ЗОНА 1: ВОСПРИЯТИЕ    │ ЗОНА 2: ВОЛНОВОД (КОРИДОР)│ ЗОНА 3: СВОБОДНЫЙ     │
 │ (Слои 0 .. l_eq-1)    │ (Слои l_eq .. l*)        │         ИНТЕЛЛЕКТ     │
 │                       │                          │ (Слои l*+1 .. L_total)│
 │ • Лексический парсинг │ • Упругий коридор R(l)   │ • λ ≡ 0 (Свобода)     │
 │ • Векторы RoPE        │ • Плоское дно: U = 0     │ • Построение логики   │
 │ • λ = 0               │ • Стенка: упругий отскок │ • Седловые точки AST  │
 └───────────────────────┴──────────────────────────┴───────────────────────┘

```

### 2.1. Зона 1: Сенсорное восприятие ($0 \le l < l_{\mathrm{eq}}$)

* **Границы:** от слоя эмбеддингов до экватора (слои $0 \dots 7$ для модели с $L=24$).
* **Физика:** парсинг токенов, расчет синтаксических зависимостей, наложение поворотных матриц позиционирования (RoPE). Вектор луча принудительно отключен: $\lambda(l) \equiv 0$. Входной текст и синтаксис считываются без внешних искажений.

### 2.2. Зона 2: Конический волновод-конфузор ($l_{\mathrm{eq}} \le l \le l^{\ast}$)

* **Границы:** от слоя экватора $l_{\mathrm{eq}}$ до рубежа пластичности $l^{\ast}$ (слои $8 \dots 12$).
* **Физика:** динамическая воронка (Semantic Funnel). Сечение волновода плавно сужается от широкого раструба входа до проектной горловины рабочего каньона по степенному закону:

$$R(l) = R_{\mathrm{target}} + (R_{\mathrm{wide}} - R_{\mathrm{target}}) \cdot \left( \frac{l^{\ast} - l}{l^{\ast} - l_{\mathrm{eq}}} \right)^{\gamma}, \quad \forall l \in [l_{\mathrm{eq}}, \; l^{\ast}]$$

где:

* $R_{\mathrm{wide}} = 0.85$ — входной радиус воронки на слое $l_{\mathrm{eq}}$;
* $R_{\mathrm{target}} = 0.35$ — радиус горловины каньона на слое $l^{\ast}$;
* $\gamma = 1.50$ — показатель профиля кривизны конфузора.

#### Разложение вектора состояния

На каждом промежуточном слое скрытый вектор $\vec{h}^{(l)}$ раскладывается относительно канонической оси $\vec{C}_{\mathrm{canon}}$:

$$\vec{h}_{\parallel}^{(l)} = \langle \vec{h}^{(l)}, \vec{C}_{\mathrm{canon}} \rangle \vec{C}_{\mathrm{canon}}, \quad \vec{h}_{\perp}^{(l)} = \vec{h}^{(l)} - \vec{h}_{\parallel}^{(l)}, \quad d_{\perp}^{(l)} = \Vert{}\vec{h}_{\perp}^{(l)}\Vert{}_2$$

#### Потенциальное поле с плоским дном

Потенциальная функция коридора $U(d_{\perp}, l)$ обеспечивает нулевое сопротивление внутри коридора допуска и резкое упругое отражение при попытке пересечения границы:

$$U(d_{\perp}, l) = \begin{cases} 0, & d_{\perp} \le R(l) \quad \text{\bf [Плоское дно: свободное мышление]} \\ \frac{1}{2} k_{\mathrm{wall}}(l) \cdot \left( d_{\perp} - R(l) \right)^{2}, & d_{\perp} > R(l) \quad \text{\bf [Упругая стенка каньона]} \end{cases}$$

Жесткость стенки плавно нарастает по мере приближения к рубежу пластичности:

$$k_{\mathrm{wall}}(l) = k_0 \cdot \left( 1 + \beta_{\mathrm{stiff}} \cdot \frac{l - l_{\mathrm{eq}}}{l^{\ast} - l_{\mathrm{eq}}} \right)$$

#### Восстанавливающая сила и коррекция внимания

Силовое воздействие луча рассчитывается как антиградиент потенциала:

$$\vec{F}_{\mathrm{restore}}(l) = -\nabla U(d_{\perp}, l) = \begin{cases} \vec{0}, & d_{\perp} \le R(l) \\ -k_{\mathrm{wall}}(l) \cdot \left( d_{\perp} - R(l) \right) \cdot \frac{\vec{h}_{\perp}^{(l)}}{d_{\perp}^{(l)}}, & d_{\perp} > R(l) \end{cases}$$

Модификация матрицы запросов в механизме внимания:

$$\tilde{q}_t^{(l,h)} = q_{\mathrm{rot}, t}^{(l,h)} + \lambda(l, t_{\mathrm{gen}}) \cdot \omega_{l,h} \cdot \left( \frac{\Vert{}q_{\mathrm{rot}, t}^{(l,h)}\Vert{}_2}{\Vert{}\vec{F}_{\mathrm{restore}}(l)\Vert{}_2 + \epsilon} \right) \vec{F}_{\mathrm{restore}}(l) W_Q^{(l,h)}$$

где $\lambda(l, t_{\mathrm{gen}}) = \lambda_0 (\exp(-t_{\mathrm{gen}} / \tau_{\mathrm{decay}}) + \lambda_{\mathrm{floor}})$ задает релаксацию импульса в фазе генерации.

### 2.3. Зона 3: Свободный интеллект и логический вывод ($l^{\ast} < l \le L_{\mathrm{total}}$)

* **Границы:** от рубежа пластичности $l^{\ast}$ до финального слоя классификатора (слои $13 \dots 24$).
* **Физика:** действие волновода полностью прекращается:

$$\forall l \in [l^{\ast} + 1, \; L_{\mathrm{total}}]: \quad \vec{F}_{\mathrm{restore}}(l) \equiv \vec{0}, \quad \lambda(l) \equiv 0$$

Вектор состояния спозиционирован строго в русле задачи. На заключительных слоях сеть рассчитывает алгоритмические ветвления, типы данных и логику на 100% мощности исходных весов. Лоботомия исключена.

## 3. Контур 2: Константный V-буфер кадра (Zami Frame Buffer)

### 3.1. Двоичная спецификация структур памяти (`zami_frame.h`)

Размер структуры кадра составляет ровно 23 488 байт. Все секции строго выровнены по 64-байтным границам кэш-линий процессора:

```c
#ifndef ZAMI_FRAME_H
#define ZAMI_FRAME_H

#include <stdint.h>

#define ZAMI_ALIGN_CACHELINE  64U

typedef enum {
    ZAMI_STATUS_EMPTY      = 0x00,
    ZAMI_STATUS_HOST_READY = 0x01, // Хост заполнил Uniform и Ingress
    ZAMI_STATUS_CORE_BUSY  = 0x02, // Ядро выполняет прямой прогон
    ZAMI_STATUS_CORE_DONE  = 0x03, // Срез Scanout доступен для хоста
    ZAMI_STATUS_FAULT      = 0xFF  // Аварийный сброс (Circuit-Breaker)
} zami_frame_status_t;

#pragma pack(push, 1)

/* Дескриптор миссии / активного уровня (4 672 байта) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_uniform_header {
    uint64_t tenant_id;            // Хэш пользователя / проекта
    uint64_t frame_seq_id;         // Монотонный счетчик кадра
    uint32_t d_model;              // Размерность скрытого состояния (напр. 896)
    uint16_t layer_equator;        // Начало волновода l_eq (8)
    uint16_t layer_plasticity;     // Рубеж пластичности l* (12)
    float    waveguide_radius_r;   // Радиус горловины R_target
    float    wall_elasticity_k;    // Жесткость стенки k_wall
    float    c_canon_vector[1024]; // Каноническая ось волновода (4 096 байт)
    uint8_t  pad[552];             // Выравнивание секции
} zami_uniform_header_t;

/* Входящий полезный кадр (4 672 байта) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_ingress_payload {
    uint32_t token_count;
    uint32_t input_tokens[1024];   // Входящие токены (4 096 байт)
    uint8_t  pad[572];             // Выравнивание секции
} zami_ingress_payload_t;

/* Срез обратной связи кадра Scanout (14 080 байт) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_scanout_feedback {
    uint32_t gen_token_count;
    uint32_t generated_tokens[512];// Сгенерированные токены (2 048 байт)
    float    h_equator_slice[1024];// Энтропийный срез экватора (4 096 байт)
    float    frame_entropy;        // Энтропия кадра H(X)
    float    orthogonal_drift;     // Отклонение ||h_perp||
    uint8_t  pad[7924];            // Выравнивание до 14 080 байт
} zami_scanout_feedback_t;

/* Полная структура буфера кадра (23 488 байт) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_frame_buffer {
    /* Кэш-линия 0: Lockless-арбитр (0x0000..0x003F) */
    volatile uint32_t       status;
    uint32_t                lock_pad;
    uint8_t                 pad0[56];

    /* Секции обмена данными */
    zami_uniform_header_t   uniform; // 4 672 байта
    zami_ingress_payload_t  ingress; // 4 672 байта
    zami_scanout_feedback_t scanout; // 14 080 байт
} zami_frame_buffer_t;

#pragma pack(pop)

#endif /* ZAMI_FRAME_H */

```

### 3.2. Lockless-арбитраж и временное разделение кадра

Синхронизация между потоком управления (`kqueue`) и вычислительным ядром (`GGML`) исключает блокировки ядра ОС:

```text
 ХОСТ (Реактор kqueue)                              НЕЙРО-ЯДРО (GGML Worker)
 ┌──────────────────────────────────────┐          ┌──────────────────────────────────────┐
 │ 1. Запись Uniform + Ingress          │          │                                      │
 │ 2. atomic_thread_fence(release)      │          │                                      │
 │ 3. atomic_store(&fb->status, READY)  │ ───────► │ 4. while (atomic_load(&fb->status)   │
 │                                      │          │           != READY) { _mm_pause(); } │
 │                                      │          │ 5. atomic_thread_fence(acquire)      │
 │                                      │          │ 6. Прямой прогон: 0 .. l_eq-1        │
 │                                      │          │ 7. Волновод: l_eq .. l*              │
 │                                      │          │ 8. Свободный синтез: l*+1 .. L       │
 │                                      │          │ 9. Запись Scanout (h_eq, H(X))       │
 │                                      │          │ 10. atomic_thread_fence(release)     │
 │ 13. while (atomic_load(&fb->status)  │ ◄─────── │ 11. atomic_store(&fb->status, DONE)  │
 │            != DONE) { _mm_pause(); } │          └──────────────────────────────────────┘
 │ 14. atomic_thread_fence(acquire)     │
 │ 15. Чтение h_equator, запуск P_U     │
 └──────────────────────────────────────┘

```

### 3.3. Энтропийно-взвешенный срез Scanout

В долговременную память $P_U$ передается вектор экватора, взвешенный обратной энтропией (служебный синтаксис исключается):

$$\vec{h}_{\mathrm{scanout}} = \frac{1}{\sum_{t \in \mathrm{Gen}} w_t + \epsilon} \sum_{t \in \mathrm{Gen}} w_t \cdot h_t^{(l_{\mathrm{eq}})}$$

$$w_t = \max\left( 0.0, \; 1.0 - \frac{H(t)}{H_{\mathrm{threshold}}} \right) \cdot \mathbb{I}(t \notin \mathrm{StopTokens})$$

### 3.4. Аварийный автомат состояний (Circuit-Breaker)

Для предотвращения каскадной деградации вычислителя при возникновении численной нестабильности ($NaN$, $\pm\infty$ в скрытых состояниях) или аномальных энтропийных всплесках ($\Delta H > H_{\mathrm{limit}}$) задействуется аппаратный автомат защиты:

1. **Немедленная изоляция волновода:** восстанавливающее воздействие луча мгновенно обнуляется:

$$\vec{F}_{\mathrm{restore}}(l) \equiv \vec{0}, \quad \lambda(l) \equiv 0$$

2. **Фиксация статуса кадра:** поток выставляет в арбитре статус `ZAMI_STATUS_FAULT` (`0xFF`) и завершает прямой прогон на стоковых весах $P_S$ без искажения базового вывода.

3. **Защита топологии:** срез Scanout бракуется и не передается в контур аккреции $P_U$, исключая разрушение дисковых барицентров бассейнов поврежденными данными.

## 4. Контур 3: Топологический ландшафт контекста ($P_U$)

### 4.1. Доменный шлюз ингресса (Domain Gatekeeper)

До выделения буфера текст проверяется по двухфакторному каскаду:

1. **Индекс технической плотности ($\rho_{\mathrm{tech}}$):**

$$\rho_{\mathrm{tech}}(D) = \frac{N_{\mathrm{sys}} + 2 \cdot N_{\mathrm{hex\_path}} + 0.3 \cdot N_{\mathrm{syntax}}}{M} \ge 0.08$$



Анализ на C11 выполняется за $< 10$ мкс на 10 КБ. При $\rho_{\mathrm{tech}} < 0.08$ кадр немедленно сбрасывается с кодом `ERR_NON_TECHNICAL_PAYLOAD` без запуска слоев трансформера (0 FLOPs).
2. **Барицентрическая аффинность Layer 0:**

$$\Phi_{\mathrm{domain}}(D) = \left\langle \frac{\sum_{t=1}^M W_E(w_t)}{\|\sum_{t=1}^M W_E(w_t)\|_2}, \; \vec{C}_{\mathrm{tech}} \right\rangle \ge 0.72$$



### 4.2. Декомпозиция Trunk-and-Branch

При сближении двух каньонов на расстояние $\|\vec{C}_A - \vec{C}_B\|_2 < 0.65 (R_A + R_B)$ запускается факторизация через индекс взаимной аффинности:

$$\mu(\vec{c}_i) = \min\left( \langle \vec{c}_i, \vec{C}_A \rangle, \; \langle \vec{c}_i, \vec{C}_B \rangle \right)$$

$$\begin{cases} \mu(\vec{c}_i) \ge \cos(\theta_{\mathrm{shared}}): & \vec{c}_i \in \mathcal{B}_{\mathrm{common}} \implies \text{Инвариантный Ствол } \mathcal{C}_{\mathrm{trunk}} \\ \mu(\vec{c}_i) < \cos(\theta_{\mathrm{shared}}) \land \vec{c}_i \in \mathcal{C}_A: & \vec{c}_i \in \mathcal{B}_{\Delta A} \implies \text{Дифференциальный рукав } \mathcal{C}_{\Delta A} \\ \mu(\vec{c}_i) < \cos(\theta_{\mathrm{shared}}) \land \vec{c}_i \in \mathcal{C}_B: & \vec{c}_i \in \mathcal{B}_{\Delta B} \implies \text{Дифференциальный рукав } \mathcal{C}_{\Delta B} \end{cases}$$

### 4.3. Гравитационная аккреция бассейнов (Basin Accretion)

Входящий срез Scanout не создает дубликатов, а притягивается к ближайшему аттрактору:

$$k^{\ast} = \arg\max_k \langle \vec{h}^{(l_{\mathrm{eq}})}, \vec{c}_k \rangle$$

Условие захвата по динамическому радиусу:

$$\|\vec{h}^{(l_{\mathrm{eq}})} - \vec{c}_{k^{\ast}}\|_2 \le R_{\mathrm{acc}}(M_{k^{\ast}}), \quad R_{\mathrm{acc}}(M) = R_{\mathrm{base}} \cdot \left( 1 + 0.25 \ln(1 + M) \right)^{-\frac{1}{2}}$$

При захвате масса аттрактора увеличивается, а барицентр смещается:

$$M_{k^{\ast}}^{(t+1)} = M_{k^{\ast}}^{(t)} + w_h, \quad \vec{c}_{k^{\ast}}^{(t+1)} = \frac{\vec{c}_{k^{\ast}}^{(t)} + \frac{w_h}{M_{k^{\ast}}^{(t+1)}} \left( \vec{h}^{(l_{\mathrm{eq}})} - \vec{c}_{k^{\ast}}^{(t)} \right)}{\left\| \vec{c}_{k^{\ast}}^{(t)} + \frac{w_h}{M_{k^{\ast}}^{(t+1)}} \left( \vec{h}^{(l_{\mathrm{eq}})} - \vec{c}_{k^{\ast}}^{(t)} \right) \right\|_2}$$

### 4.4. Емкостной лимит рукавов и топологический митоз

Емкость одного рукава строго ограничена $K_{\mathrm{cap}} = 32$ бассейнами (дескриптор ровно 4 096 байт — страница памяти ОС). При попытке добавления 33-го бассейна:

* **Микро-коллапс:** если внутренняя дисперсия $\mathrm{Var}(\mathcal{B}_{\Delta}) < 0.15$, два наиболее близких бассейна объединяются.
* **Митоз рукава:** если дисперсия $\ge 0.15$, рукав делится гиперплоскостью первой главной компоненты (PCA) на два независимых рукава-сиблинга по 16 бассейнов.

### 4.5. Термодинамика жизненного цикла и прерывание Cold-Fault

Жизнеспособность рукава описывается термальной энергией:

$$V(b, t) = \sum_{k} \exp\left( -\frac{t - t_k}{\tau_{\mathrm{decay}}} \right), \quad \tau_{\mathrm{decay}} = 48 \text{ часов}$$

* При $V(b, t) < 0.05$ рукав эвакуируется в сжатый пул ZFS (`lz4`), а в памяти ствола сохраняется 32-байтный `GhostAnchor`.
* При повторном запросе по условию $\langle \vec{q}, \vec{C}_{\mathrm{cold}} \rangle \ge \cos(\theta_{\mathrm{wake}})$ вызывается асинхронное прерывание **Cold-Fault** (восстановление страниц пула через `kqueue` за $t < 0.5$ мс).

### 4.6. Принцип дуализма внимания: Изоморфизм контекстной и семантической памяти

Архитектура ZamiCore исключает применение внешних векторных индексов (k-NN/HNSW). Физическая иерархия данных на диске («Стволы — Рукава — Бассейны») представляет собой прямое пространственное отображение многоуровневого оператора внимания (**Hierarchical Tree Attention**):

1. **Слой внимания Стволов (Macro-Routing):** срез экватора $\vec{h}^{(l_{\mathrm{eq}})}$ определяет глобальный домен задачи через верхний уровень Softmax:

$$\alpha_{\mathrm{trunk}} = \mathrm{softmax}\left( \frac{\vec{h}^{(l_{\mathrm{eq}})} \mathbf{C}_{\mathrm{trunks}}^{T}}{\tau \sqrt{d_{\mathrm{model}}}} \right)$$

2. **Слой внимания Рукавов (Meso-Routing):** селекция целевого дифференциального рукава внутри активного ствола:

$$\alpha_{\mathrm{branch}} = \mathrm{softmax}\left( \frac{\vec{h}^{(l_{\mathrm{eq}})} \mathbf{C}_{\mathrm{branches}}^{T}}{\tau \sqrt{d_{\mathrm{model}}}} \right)$$

3. **Слой внимания Бассейнов (Micro-Routing):** локальный Softmax по 32 бассейнам в пределах единственной 4 КБ страницы ZFS, прочитанной с NVMe:

$$\alpha_{\mathrm{basin}} = \mathrm{softmax}\left( \frac{\vec{h}^{(l_{\mathrm{eq}})} \mathbf{C}_{\mathrm{page32}}^{T}}{\tau \sqrt{d_{\mathrm{model}}}} \right)$$

Факторизация каньонов и отсечение расходящихся рукавов выступают динамическим расширением графа Softmax, сохраняя логарифмическую вычислительную сложность выборки $O(\log N)$ и детерминированный аппаратный отклик накопителя NVMe.

* **Контекстная память кадра (Динамический контур):** локализована во времени внутри V-буфера и слоев волновода. Представляет собой кинетическую траекторию смещения скрытого вектора $\vec{h}^{(l)}$ под воздействием упругого коридора.
* **Семантическая память ландшафта (Статический контур):** пространственно развернута на дисковых страницах NVMe/ZFS в виде барицентров бассейнов $\vec{c}_k$. 

Навигация по диску представляет собой операцию Cross-Attention, где вектор экватора выступает проекционным запросом к неизменяемому семантическому базису:

$$\mathcal{A}_{\mathrm{topo}} = \mathrm{softmax}\left( \frac{\vec{h}^{(l_{\mathrm{eq}})} \cdot \mathbf{C}_{\mathrm{basins}}^T}{\sqrt{d_{\mathrm{model}}}} \right)$$

Таким образом, долговременная память ZamiCore не является классической базой данных, а функционирует как замороженный, дискретизированный терминальный слой внимания нейро-ядра, вынесенный на твердотельный накопитель.


**Топологический митоз как динамическое расширение графа внимания:**  
Операция факторизации каньонов (Trunk-and-Branch) и отсечение расходящихся рукавов не является механическим перемещением файлов. Это динамическое порождение нового узла в дереве Softmax. Выделение зрелого рукава в самостоятельный инвариантный ствол добавляет строку в матрицу проекций верхнего уровня, сохраняя логарифмическую сложность выборки $O(\log N)$ и детерминированное время аппаратного отклика накопителя.

## 5. Физический уровень хранения NVMe/ZFS и подсистема I/O (FreeBSD 14+)

> **Примечание об архитектурной нейтральности:**  
> Все уравнения волновода, формат V-буфера и дисковая топология ZamiCore являются **моделе-независимыми** (Model-Agnostic) и применимы к любой архитектуре авторегрессионного декодера (Dense Transformer, MoE).  
> Семейство моделей **Qwen 2.5 (0.5B – 14B)** выступает в качестве открытого эталонного стенда (Reference Baseline) для первичной калибровки весов волновода и верификации задержек ABI на FreeBSD.
Вся топология $P_U$ размещается на постоянных твердотельных накопителях (NVMe) под управлением OpenZFS. Механика ввода-вывода полностью исключает хранение контекста в оперативной памяти ускорителя.

```text
========================================================================================
             ТОПОЛОГИЯ ДИСКОВОГО ПУЛА ZFS (КРАТНОСТЬ СТРАНИЦЕ PAGE_SIZE = 4096)
========================================================================================

  zdata/zamicore/
  ├── static/                     # ashift=12, compression=lz4, readonly=on
  │   └── qwen2.5-0.5b.gguf      # Неизменяемый базис весов P_S
  └── tenants/
      └── {tenant_hash}/          # recordsize=4k, compression=lz4, atime=off
          ├── trunk.bin           # Ствол каньона: 4096 байт (Заголовок + Инварианты)
          ├── branches/           # Рукава контекста (Каждый файл строго 4096 байт)
          │   ├── branch_001.bin  # 32 активных бассейна (128 байт * 32 = 4096 байт)
          │   └── branch_002.bin  # Разреженный файл (Punch Hole / SPACECTL_DEALLOC)
          └── ghost_anchors.bin   # Таблица призрачных якорей для Cold-Fault

```

### 5.1. Конфигурация пула ZFS для детерминированного отклика

Для устранения накладных расходов планировщика ввода-вывода пул форматируется со следующими параметрами:

* `ashift=12`: строгое аппаратное выравнивание по 4096-байтным секторам современных SSD (Advanced Format 4Kn).
* `recordsize=4k`: размер блока файловой системы равен размеру страницы виртуальной памяти ядра FreeBSD (`PAGE_SIZE`). Любая операция чтения дескриптора рукава представляет собой ровно одну страницу I/O.
* `compression=lz4`: прозрачное сжатие холодного контекста без загрузки процессорных конвейеров.
* `atime=off`: отключение модификации времени доступа, устраняющее паразитные операции записи метаданных.

### 5.2. Бинарный контракт дискового формата (`zami_storage_layout.h`)

Каждый узел топологии строго упакован в структуры с размерами, кратными степеням двойки:

```c
#ifndef ZAMI_STORAGE_LAYOUT_H
#define ZAMI_STORAGE_LAYOUT_H

#include <stdint.h>

#define ZAMI_DISK_PAGE_SIZE    4096U
#define ZAMI_BASINS_PER_BRANCH 32U

#pragma pack(push, 1)

/* 1. Дескриптор бассейна на диске (ровно 128 байт) */
typedef struct {
    float    centroid[24];      // Барицентр бассейна (96 байт, сжатая проекция)
    float    mass_weight;       // Аккреционная масса (4 байта)
    float    dispersion_r;      // Локальный радиус рассеяния (4 байта)
    uint32_t last_touch_epoch;  // Временная метка для расчета тепловой энергии (4 байта)
    uint32_t token_anchor_id;   // Ссылка на ключевой токен синтаксиса (4 байта)
    uint8_t  reserved[16];      // Дополнение до 128 байт
} zami_basin_disk_t;

/* 2. Дескриптор рукава на диске (ровно 4096 байт — 1 страница ОС) */
typedef struct {
    uint64_t          branch_id;                         // Идентификатор рукава (8 байт)
    uint64_t          parent_trunk_id;                   // Ссылка на родительский ствол (8 байт)
    uint32_t          basin_count;                       // Текущее число бассейнов (до 32)
    float             thermal_energy;                    // Текущий уровень тепла V(b, t)
    uint8_t           flags;                             // Флаги (ACTIVE = 0, HIBERNATED = 1)
    uint8_t           pad_hdr[35];                       // Выравнивание заголовка до 64 байт
    zami_basin_disk_t basins[ZAMI_BASINS_PER_BRANCH];    // 32 * 128 байт = 4032 байта
    uint8_t           page_tail_pad[0];                  // ИТОГО: ровно 4096 байт!
} zami_branch_disk_t;

/* 3. Дескриптор призрачного якоря спящего рукава (32 байта) */
typedef struct {
    uint64_t branch_id;         // ID выгруженного рукава
    float    c_wake_vector[4];  // Сигнатурная проекция для пробуждения (16 байт)
    float    wake_threshold;    // Порог пробуждения cos(theta_wake) (4 байта)
    uint32_t disk_block_offset; // Смещение блока в пуле ZFS (4 байта)
} zami_ghost_anchor_t;

#pragma pack(pop)

#endif /* ZAMI_STORAGE_LAYOUT_H */

```

### 5.3. Механика ввода-вывода ядра FreeBSD

#### Zero-Copy маппинг (`mmap` + `madvise`)

При активации миссии управляющий демон проецирует файл ствола `trunk.bin` и активные рукава в адресное пространство процесса:

```c
int fd = open("zdata/zamicore/tenants/0x4F/branches/branch_001.bin", O_RDWR | O_DIRECT);
void* addr = mmap(NULL, ZAMI_DISK_PAGE_SIZE, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

// Упреждающая загрузка страницы в кэш процессора без блокировок
madvise(addr, ZAMI_DISK_PAGE_SIZE, MADV_WILLNEED);

```

После завершения прямого прогона неактивные страницы маркируются флагом `MADV_DONTNEED`, возвращая физическую страницу в пул ОС без задержек.

#### Разреженный анабиоз (Punch-Hole via `fspacectl`)

Если термальная энергия рукава опускается ниже критического порога:

$$V(b, t) < 0.05$$

рукав отправляется в спящий режим. Чтобы освободить физические блоки NVMe без изменения структуры дескрипторов файлов, ядро вызывает системный вызов FreeBSD `fspacectl(2)`:

```c
struct spacectl_range range = {
    .r_offset = 0,
    .r_len    = ZAMI_DISK_PAGE_SIZE
};

// Физическое освобождение блоков SSD при сохранении дескриптора файла
fspacectl(fd, SPACECTL_DEALLOC, &range, 0, NULL);

```

Файл становится разреженным (`sparse`), его физический вес на SSD обнуляется, а на ствол проецируется 32-байтный `zami_ghost_anchor_t`.

#### Асинхронное прерывание Cold-Fault на очередях ядра (`kqueue`)

Если во время инференса вектор скрытого состояния $\vec{h}^{(l_{\mathrm{eq}})}$ генерирует проекцию на спящий якорь:

$$\langle \vec{h}^{(l_{\mathrm{eq}})}, \vec{C}_{\mathrm{cold}} \rangle \ge \cos(\theta_{\mathrm{wake}})$$

генерируется аппаратное программное прерывание **Cold-Fault**:

1. Вычислительный поток ядра не блокируется в ожидании дискового ввода-вывода.
2. В очередь ядра `kqueue(2)` передается асинхронный дескриптор `EVFILT_AIO` на вычитку блоков через OpenZFS.
3. Страница декомпрессируется из LZ4 за $t < 0.45$ миллисекунды и проецируется в память.
4. Поток волновода восстанавливает координаты каньона и продолжает генерацию без срыва контекста.

### 5.4. Мгновенное ветвление проектов через Copy-on-Write ($O(1)$)

Если пользователю требуется создать параллельную ветку рассуждений (альтернативное решение, тестовый рефакторинг), система не дублирует гигабайты KV-кэша. Выполняется атомарный моментальный снимок (snapshot) и создание клона ZFS:

```sh
zfs snapshot zdata/zamicore/tenants/task_A@branch_point
zfs clone zdata/zamicore/tenants/task_A@branch_point zdata/zamicore/tenants/task_B

```

Операция завершается за **0 миллисекунд** и физически занимает **0 байт** на диске. Новые бассейны пишутся в дельту `task_B`, оставляя базовый контекст `task_A` неизменным.

## 6. Межмодельная миграция и масштабирование (Мост Прокруста)

### 6.1. Детерминированное заземление токенов при проекции Прокруста

Межмодельный перенос топологии ($\mathcal{M}_A \to \mathcal{M}_B$) строго разграничивает проекцию семантических координат и представление артефактов:

* **Инвариант артефакта (Ground Truth):** исходный код удерживается в фиксированных массивах токенов или байтовых блоках CAS. Снапшоты системы фиксируют неизменяемое тело программы, исключая вероятностную регенерацию исходного текста при смене модели-вычислителя.
* **Изоморфизм словарей:** внутри модельных семейств с унифицированным пространством эмбеддингов массив `base_page_tokens` переносится без трансляции ($O(1)$ по времени).
* **Эластичное масштабирование страницы:** размер рабочего окна модификации адаптируется под размерность $d_{\mathrm{model}}$ целевой модели (от 1 024 токенов для компактных моделей до 4 096+ токенов для старших архитектур) путем компоновки дополнительных 4 КБ блоков ZFS без модификации топологического графа.
При переносе топологического ландшафта между различными моделями ($\mathcal{M}_A \to \mathcal{M}_B$, где $d_A \neq d_B$) система не выполняет повторную токенизацию истории.

На универсальном наборе из $K = 512$ семантических инвариантов $\mathcal{S}_{\mathrm{anchor}}$ рассчитывается аналитическая матрица перехода через регуляризацию Тихонова:

$$W_{A \to B} = \left( \tilde{X}_A^{T} \tilde{X}_A + \alpha I_{d_A} \right)^{-1} \tilde{X}_A^{T} \tilde{X}_B \quad \in \mathbb{R}^{d_A \times d_B}$$

Координаты всех сохраненных на диске бассейнов трансформируются за $t < 20$ мс:

$$\vec{c}_k^{(B)} = \frac{\vec{c}_k^{(A)} W_{A \to B}}{\|\vec{c}_k^{(A)} W_{A \to B}\|_2}$$

### Эффект латентного раскрытия (Latent Expansion)

Координаты каньона, сохраненные легкой моделью ($0.5$B, $d=896$), при переносе в фазовое пространство тяжелой модели ($14$B, $d=5120$) позиционируются в ту же предметную область.

Однако за счет возросшей размерности тяжелая модель оперирует на порядок более детальным набором внутренних микро-бассейнов внутри того же самого контекста, обеспечивая глубокий анализ кода и дампов без повторного ввода исходных документов.

| **Контекстный дрейф ($t > 10^{4}$ токенов)** | Необратимый уход ($> 65\%$) | **0.00%** (Упругий волновод $R$) |
| **Сложность переключения контекста** | $O(N)$ (Смена KV-кэша) | **$O(1)$** (Подмена Uniform за 256 нс) |
| **Задержка шага волновода (AVX2)** | N/A | **Менее 38 нс** на вектор |
| **Время разветвления диалога/задачи** | $O(N)$ (Дублирование памяти) | **$O(1)$** (0 мс, CoW ZFS Clone) |

### 8. Контур 4: Подсистема артефактов кода и шлюз верификации (Code Artifact Subsystem / CAS)

При переходе от текстового диалога к детерминированному анализу и рефакторингу программного кода активируется специализированный режим **`MODE_REFACTOR`**. Архитектура полностью исключает хранение исходного кода в вероятностном векторном пространстве, разделяя семантический индекс и физические файлы на диске.

```text
========================================================================================
            ТРЕХЗВЕННАЯ МОДЕЛЬ ПАМЯТИ И АРТЕФАКТОВ ZAMICORE (MODE_REFACTOR)
========================================================================================

 ┌────────────────────────────────────────────────────────────────────────────────────┐
 │ 1. ТОПОЛОГИЧЕСКИЙ ЛАНДШАФТ (P_U): "Куда думать" (Координаты смыслов)                │
 │    • Векторные каньоны и бассейны на NVMe/ZFS (4 096 байт на страницу)             │
 │    • Хранит только 32-байтные криптографические хэши BLAKE3 и ссылки на AST-узлы  │
 └─────────────────────────┬──────────────────────────────────────────────────────────┘
                           │ Разрешение хэша за < 15 мкс
                           ▼
 ┌────────────────────────────────────────────────────────────────────────────────────┐
 │ 2. ДЕТЕРМИНИРОВАННЫЙ КАНОН (P_C): "Что есть истина" (Физический код на ZFS)        │
 │    • Неизменяемые исходники в Content-Addressable Storage (CAS): /objects/{hash}.c │
 │    • Только код, прошедший валидацию компилятором (Exit Code = 0)                  │
 │    • Хост поднимает страницу функции в RAM ровно ОДИН раз (Read-Only)              │
 └────────────────────────────────────────────────────────────────────────────────────┘
                           ▲
                           │ ШЛЮЗ ВЕРИФИКАЦИИ (Promotion Gate):
                           │ Clang AST / -fsyntax-only / Тесты
 ┌─────────────────────────┴──────────────────────────────────────────────────────────┐
 │ 3. ЭФЕМЕРНЫЙ БУФЕР КАНДИДАТОВ (P_τ): "Операционный стол" (Черновик в RAM)          │
 │    • Выделяется в оперативной памяти (FreeBSD tmpfs / md(4) scratchpad)            │
 │    • Сюда Зона 3 трансформера потоково пишет генерируемый патч или новую функцию   │
 │    • 0 байт износа NVMe: при синтаксической ошибке сгорает в RAM без следа         │
 └────────────────────────────────────────────────────────────────────────────────────┘

```

### 8.1. Разделение обязанностей: Модель-генератор и Системный арбитр

Нейросеть не определяет статус истинности сгенерированного кода. Модель является исключительно «генератором гипотез» (*Proposer*), а арбитром канона выступает системный рантайм FreeBSD (*Verifier*):

1. **Флаг намерений в V-буфере (`intent_mode`):**
Хост явно указывает модели задачу: `OP_NEW_MODULE` (генерация с нуля), `OP_REFACTOR_PATCH` (модификация канона) или `OP_FIX_ERROR` (исправление синтаксической ошибки с передачей лога компилятора).
2. **Сигнальный протокол генерации (Output Framing):**
На свободных терминальных слоях Зоны 3 модель генерирует код, обрамленный жесткими синтаксическими маркерами (или структурированный через GBNF-маску). По достижении терминального токена генерация мгновенно останавливается, а управление возвращается демону хоста.
3. **Классификация состояний артефакта:**
* **`CANDIDATE_TRANSIENT` (Черновик):** код находится в оперативной памяти ($P_\tau$). Не виден контексту $P_U$.
* **`CANON_PROMOTED` (Канон):** код успешно скомпилирован (`clang -fsyntax-only` вернул 0). Хэшируется через BLAKE3, атомарно сбрасывается в хранилище `/objects/{hash}.c` на ZFS, а дескриптор бассейна $P_U$ обновляет ссылку.
* **`ANTI_CANON` (Отрицательный опыт):** если модель повторяет синтаксическую или архитектурную ошибку, вектор бракованного черновика инвертируется по знаку. Волновод $U(d_\perp)$ превращает его в отталкивающий барьер, не позволяя лучу внимания повторять ту же ошибку при следующей итерации.
* **Изоляция компиляторного шлюза (Capsicum Sandbox):**  
Вызов `clang -fsyntax-only` над непроверенным буфером $P_\tau$ выполняется в изолированном контексте песочницы FreeBSD `capsicum(4)` (режим `cap_enter(2)`). Процессу верификатора запрещен доступ к сети, сокетам IPC и файловой системе вне выделенного дескриптора буфера черновика. Это нейтрализует векторы атак через рекурсивные макросы, бомбы препроцессора (`#include "/dev/urandom"`) и уязвимости парсера AST.

### 8.2. Двоичные структуры окна модификации и графа версий (`zami_code_mode.h`)

В режиме кодогенерации полезная нагрузка V-буфера переключается на окно модификации, а на диске формируется направленный ациклический граф (DAG) изменений:

```c
#ifndef ZAMI_CODE_MODE_H
#define ZAMI_CODE_MODE_H

#include <stdint.h>
#include "zami_frame.h"

#define ZAMI_CODE_PAGE_TOKENS  1024U

#pragma pack(push, 1)

/* Дескриптор кадра модификации кода (4 672 байта) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_refactor_payload {
    uint8_t  base_artifact_blake3[32];               // Хэш исходного канона P_C
    uint32_t base_page_token_count;                  // Размер исходной страницы
    uint32_t base_page_tokens[ZAMI_CODE_PAGE_TOKENS];// Исходный код (4 096 байт)
    uint32_t diff_intent_tokens[128];                // Инструкция задачи (512 байт)
    uint8_t  pad[28];                                // Выравнивание до 4 672 байт
} zami_refactor_payload_t;

/* Эфемерный слот кандидата в оперативной памяти (4 160 байт в RAM / tmpfs) */
typedef struct alignas(ZAMI_ALIGN_CACHELINE) zami_candidate_scratchpad {
    uint64_t session_id;
    uint32_t candidate_token_count;
    uint32_t candidate_tokens[ZAMI_CODE_PAGE_TOKENS];// Сгенерированный черновик
    uint8_t  blake3_digest[32];                      // Предварительный хэш
    uint8_t  compiler_exit_code;                     // 0 = Успех, >0 = Ошибка
    uint8_t  pad[23];
} zami_candidate_scratchpad_t;

/* Дескриптор узла графа версий артефакта (128 байт на ZFS) */
typedef struct {
    uint8_t  artifact_blake3[32];        // Хэш текущей ревизии
    uint8_t  parent_blake3[32];          // Хэш базовой версии (для отката за O(1))
    uint64_t timestamp_epoch;            // Время фиксации
    uint32_t ast_node_id;                // Идентификатор функции в AST проекта
    uint16_t byte_size;                  // Размер физического исходника в байтах
    uint8_t  verified_flags;             // Битовая маска проверок (AST, Linter, Test)
    uint8_t  reserved[49];               // Выравнивание до 128 байт
} zami_artifact_manifest_t;

#pragma pack(pop)

#endif /* ZAMI_CODE_MODE_H */

```

### 8.3. Детерминированный откат и история версий ($O(1)$)

Промежуточные компилируемые версии кода не раздувают контекст инференса. Каждая утвержденная ревизия сохраняется как неизменяемый BLAKE3-блок на ZFS. За счет связи `parent_blake3` система поддерживает мгновенный откат репозитория к любому историческому канону за 256 наносекунд путем простой подмены хэша в дескрипторе бассейна $P_U$.

### 8.4. Влияние на плотность параллельного обслуживания

В режиме рефакторинга рабочий набор памяти сессии увеличивается до ~40–48 КБ (V-буфер 23.4 КБ + страница канона в RAM 4 КБ + буфер кандидата $P_\tau$ 4.1 КБ + дескриптор ZFS 4 КБ):

| Метрика конвейера | Текстовый режим (Диалог / Поиск) | Режим кодогенерации (`MODE_REFACTOR`) |
| --- | --- | --- |
| **Рабочий набор на сессию в RAM** | **~27.4 КБ** (V-Buffer + ZFS Page) | **~40.0 – 48.0 КБ** (Включая Scratchpad) |
| **Параллельных сессий на 16 ГБ ОЗУ** | **> 500 активных сессий** | **300 – 400 активных сессий** |
| **Нагрузка на запись NVMe при генерации** | 0 байт (Только срез Scanout) | **0 байт** (Сброс на SSD только после Clang) |
| **Защита кодовой базы от галлюцинаций** | Базовая доменная фильтрация | **100% синтаксический компиляторный шлюз** |
